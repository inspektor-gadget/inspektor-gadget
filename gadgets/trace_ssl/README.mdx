# trace ssl

Captures data on read/recv or write/send functions of OpenSSL, GnuTLS, NSS and Libcrypto

## Getting started

Running the gadget:

<Tabs groupId="env">
    <TabItem value="kubectl-gadget" label="kubectl gadget">
        ```bash
        $ kubectl gadget run ghcr.io/inspektor-gadget/gadget/trace_ssl:%IG_TAG% [flags]
        ```
    </TabItem>

    <TabItem value="ig" label="ig">
        ```bash
        $ sudo ig run ghcr.io/inspektor-gadget/gadget/trace_ssl:%IG_TAG% [flags]
        ```
    </TabItem>
</Tabs>

## Flags

### `--record-data`

controls whether the gadget will send data to userspace

Default value: "true"

## Guide

This example shows how to use this gadget.

First, we need to run an application that generates some events. In this case, we'll use a pod that makes an HTTPS request to example.com every few seconds:

<Tabs groupId="env">
  <TabItem value="kubectl-gadget" label="kubectl gadget">
```bash
$ kubectl run --restart=Never --image=curlimages/curl mypod -- sh -c 'while /bin/true ; do curl -s https://example.com > /dev/null ; sleep 3 ; done'
pod/mypod created
```
  </TabItem>

  <TabItem value="ig" label="ig">
```bash
$ docker run --name test-trace-ssl -d curlimages/curl sh -c 'while /bin/true ; do curl -s https://example.com > /dev/null ; sleep 3 ; done'
```
  </TabItem>
</Tabs>

Then, let's run the gadget:

<Tabs groupId="env">
  <TabItem value="kubectl-gadget" label="kubectl gadget">
Using the trace_ssl gadget, we can see the data that the processes send and receive over SSL connections.
We can simply filter for the pod "mypod" and omit specifying the node,
thus tracing on all nodes for a pod called "mypod":

```bash
$ kubectl gadget run trace_ssl:%IG_TAG% --podname mypod
K8S.NODE           K8S.NAMESPACE K8S.PODNAME   K8S.CONTAINE… COMM        PID     TID OPERATION   LATENCY_NS BUF
minikube-docker    default       mypod         mypod         curl     720451  720451 write            21034 GET / HTTP/1.1
Host: example.c…
minikube-docker    default       mypod         mypod         curl     720451  720451 write              912 User-Agent: curl/8.9.1
Accept:…
minikube-docker    default       mypod         mypod         curl     720451  720451 read             45210 HTTP/1.1 200 OK
Accept-Ranges:…
minikube-docker    default       mypod         mypod         curl     720451  720451 read              1876 <!doctype html><html lang="en">…
minikube-docker    default       mypod         mypod         curl     720451  720451 write            19877 GET / HTTP/1.1
Host: example.c…
minikube-docker    default       mypod         mypod         curl     720451  720451 read             39812 HTTP/1.1 200 OK
Accept-Ranges:…
^C
```

The gadget captures the data passed to the SSL read and write functions, so the BUF column shows the unencrypted data: for write operations it shows the data before it is encrypted, and for read operations it shows the data after it is decrypted. In this example, we can see the plain HTTP request sent by curl and the response returned by the server, even though the connection itself is encrypted with TLS.
The LATENCY_NS column shows how much time the process spent in the SSL function.
We can stop the gadget by hitting Ctrl-C.

  </TabItem>
